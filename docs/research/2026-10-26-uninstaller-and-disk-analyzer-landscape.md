# Uninstaller and disk-analyzer landscape: primary-source notes

**Date:** 2026-10-26 · **Scope:** Geek Uninstaller 1.6 / WizTree 4.33 as closed-source comparators; open-source techniques for PurgeKit. Code links are pinned to reviewed commits. Closed-source internals are only asserted where the vendor documents them; otherwise marked **not verified**.

## Executive summary

BCU is the richest reference: multiple factories, Sift4-based leftover confidence (not Jaro-Winkler), known-folder denial, Recycle Bin deletion, `.reg` export and restore points; it lacks cross-user enumeration and fast MFT scanning. Windows correctness hinges on MSI product-code uninstall, per-user contexts, 32/64-bit views and Appx provisioning. WizTree/Everything/WinDirStat 2 read the NTFS MFT; WinDirStat 2 is the best GPL implementation, and Rust crates exist but no turnkey scanner. Czkawka contributes size→prehash→hash and `file_id` hardlink dedupe; BleachBit contributes XML rules and protected-path warnings, not rollback. PurgeKit already has quarantine, Restart Manager, `MoveFileEx`, USN tracking and signature checks; gaps are inventory correctness, portable discovery, MFT/duplicate analysis, and rules/export.

## 1. Bulk Crap Uninstaller

**Discovery.** [`RegistryFactory.GetParentRegistryKeys`](https://github.com/Klocman/Bulk-Crap-Uninstaller/blob/30da609/source/UninstallTools/Factory/RegistryFactory.cs#L284-L305) reads `HKLM` and `HKCU` `...\CurrentVersion\Uninstall`, plus both `Wow6432Node` variants only in a 64-bit process. It maps the documented ARP values and tolerates non-numeric EstimatedSize ([`GetEstimatedSize`](https://github.com/Klocman/Bulk-Crap-Uninstaller/blob/30da609/source/UninstallTools/Factory/RegistryFactory.cs#L149-L161)). Other factories cover Store (`StoreAppHelper.exe /query`), Steam (`SteamHelper l /i`, orphaned games), Chocolatey, Scoop, Oculus, Features/Updates, scripts and predefined entries ([`Factory/`](https://github.com/Klocman/Bulk-Crap-Uninstaller/tree/30da609/source/UninstallTools/Factory)). Portable/unknown apps come from [`DirectoryFactory`](https://github.com/Klocman/Bulk-Crap-Uninstaller/blob/30da609/source/UninstallTools/Factory/DirectoryFactory.cs): scan Program Files and custom roots plus `Portable*`/`LiberKey` dirs on fixed/removable drives, depth ≤2, skip known folders, claimed dirs and folders with >40 executables, then infer metadata from the best executable; results get `IsRegistered=false`, `IsOrphaned=true` ([`CreateFromDirectoryHelper`](https://github.com/Klocman/Bulk-Crap-Uninstaller/blob/30da609/source/UninstallTools/Factory/DirectoryFactory.cs#L185-L281)). It does **not** read other users' `HKU\<SID>` hives.

**Command parsing.** [`GetUninstallString`](https://github.com/Klocman/Bulk-Crap-Uninstaller/blob/30da609/source/UninstallTools/Factory/RegistryFactory.cs#L178-L201) falls back to QuietUninstallString, and `GetKeyFuzzy` accepts hidden variants such as `UninstallString_hidden`. [`UninstallManager.RunUninstaller`](https://github.com/Klocman/Bulk-Crap-Uninstaller/blob/30da609/source/UninstallTools/Uninstaller/UninstallManager.cs#L70-L150) splits argv with `ProcessTools.SeparateArgsFromCommand`, starts with `UseShellExecute=true`, falls back to the raw string if parsing throws, prefers quiet when `QuietUninstallPossible`, and minimises CLI quiet uninstallers. MSI entries bypass the string: [`GetMsiString`](https://github.com/Klocman/Bulk-Crap-Uninstaller/blob/30da609/source/UninstallTools/Uninstaller/UninstallManager.cs#L238-L256) emits `MsiExec.exe /qb /X{GUID} REBOOT=ReallySuppress /norestart`. Validation is thin (a `Debug.Assert` that the exe exists); BCU trusts registry data more than PurgeKit does.

**Leftovers.** [`JunkManager.FindJunk`](https://github.com/Klocman/Bulk-Crap-Uninstaller/blob/30da609/source/UninstallTools/Junk/JunkManager.cs) reflection-loads every `IJunkCreator`, dedupes by display name, removes self paths, and drops exact matches to known folders (CSIDL + WinRT `KnownFolders`). Matching is **Sift4**, not Jaro-Winkler: [`MatchStringToProductName`](https://github.com/Klocman/Bulk-Crap-Uninstaller/blob/30da609/source/UninstallTools/Junk/Confidence/ConfidenceGenerators.cs) rejects strings ≤4 chars, retries after trimming the publisher, accepts containment as score 2, and cuts off at one-third edit distance. [`TestForSimilarNames`](https://github.com/Klocman/Bulk-Crap-Uninstaller/blob/30da609/source/UninstallTools/Junk/Confidence/ConfidenceGenerators.cs) penalises ambiguous matches (e.g. “AppX Extended” vs “AppX”). Scores aggregate into Bad/Questionable/Good/VeryGood; the UI selects up to Good by default ([`JunkRemoveWindow`](https://github.com/Klocman/Bulk-Crap-Uninstaller/blob/30da609/source/BulkCrapUninstaller/Forms/Windows/JunkRemoveWindow.cs#L395-L434)). Finders cover install-location, software-key recursion (depth ≤1, blacklist), uninstall-key ghosts, MSI Products/Features/Patches/UserData, shortcuts, startup, firewall, COM, Prefetch and WER ([`Junk/Finders`](https://github.com/Klocman/Bulk-Crap-Uninstaller/tree/30da609/source/UninstallTools/Junk/Finders)); [`SoftwareRegKeyScanner`](https://github.com/Klocman/Bulk-Crap-Uninstaller/blob/30da609/source/UninstallTools/Junk/Finders/Registry/SoftwareRegKeyScanner.cs) adds explicit-connection confidence for `InstallDir`/`ExePath` values inside InstallLocation and mirrors keys across HKLM/HKCU/Wow.

**Safety/UX worth copying.** Files go to the Recycle Bin ([`FileSystemJunk.Delete`](https://github.com/Klocman/Bulk-Crap-Uninstaller/blob/30da609/source/UninstallTools/Junk/Containers/FileSystemJunk.cs)); registry keys are exported to `.reg` before deletion ([`RegistryKeyJunk.Backup`](https://github.com/Klocman/Bulk-Crap-Uninstaller/blob/30da609/source/UninstallTools/Junk/Containers/RegistryKeyJunk.cs)); a restore point is offered before batch runs. [`BulkUninstallTask`](https://github.com/Klocman/Bulk-Crap-Uninstaller/blob/30da609/source/UninstallTools/Uninstaller/BulkUninstallTask.cs) supports concurrency limits, one loud uninstaller at a time, type-collision avoidance, retry, auto-kill and simulation.

## 2. Windows uninstall correctness

- **Registry contract.** Microsoft documents the MSI-written ARP values (DisplayName, DisplayVersion, Publisher, InstallLocation, InstallSource, EstimatedSize, UninstallString, ModifyPath, URLs) under `HKLM\Software\Microsoft\Windows\CurrentVersion\Uninstall\{ProductCode}` ([Uninstall Registry Key](https://learn.microsoft.com/en-us/windows/win32/msi/uninstall-registry-key)). EstimatedSize is **kilobytes** ([Property Reference / ARPSIZE](https://learn.microsoft.com/en-us/windows/win32/msi/property-reference)). `SystemComponent=1` maps to `ARPSYSTEMCOMPONENT`, which only hides the product ([ARPSYSTEMCOMPONENT](https://learn.microsoft.com/en-us/windows/win32/msi/arpsystemcomponent)). `QuietUninstallString` has **no Microsoft Learn reference**; treat it as a convention (unverified).
- **MSI.** Use `MsiEnumProductsEx` with `szUserSid=s-1-1-0` and the USERMANAGED/USERUNMANAGED/MACHINE contexts, then `MsiGetProductInfoEx`; cross-user access needs admin ([MsiEnumProductsEx](https://learn.microsoft.com/en-us/windows/win32/api/msi/nf-msi-msienumproductsexa), [MsiGetProductInfoEx](https://learn.microsoft.com/en-us/windows/win32/api/msi/nf-msi-msigetproductinfoexa)). Plain `MsiEnumProducts` is not the cross-user API ([MsiEnumProducts](https://learn.microsoft.com/en-us/windows/win32/api/msi/nf-msi-msienumproductsw)). `msiexec /I{GUID}` in UninstallString means install/configure; `/x` uninstalls, `/qn`/`/qb` quiet, and `REBOOT=ReallySuppress` suppresses restart ([Command-Line Options](https://learn.microsoft.com/en-us/windows/win32/msi/command-line-options)).
- **32/64-bit views.** `HKLM\Software` is redirected to `Wow6432Node` for 32-bit callers; the physical path is reserved, so use `KEY_WOW64_32KEY`/`KEY_WOW64_64KEY` ([Registry Redirector](https://learn.microsoft.com/en-us/windows/win32/winprog64/registry-redirector)).
- **Appx.** `RemovePackageAsync` removes **for the current user**; the payload remains if another user installed it ([RemovePackageAsync](https://learn.microsoft.com/en-us/uwp/api/windows.management.deployment.packagemanager.removepackageasync)). `Remove-AppxPackage -AllUsers` needs admin; `-User` takes a SID ([Remove-AppxPackage](https://learn.microsoft.com/en-us/powershell/module/appx/remove-appxpackage)). Removing the installed package does **not** remove provisioning; use `Remove-AppxProvisionedPackage -Online` ([docs](https://learn.microsoft.com/en-us/powershell/module/dism/remove-appxprovisionedpackage)).
- **Pending reboot.** `MoveFileEx(..., MOVEFILE_DELAY_UNTIL_REBOOT)` writes `PendingFileRenameOperations`; it is admin-only, local-volume only, cannot combine with copy-allowed, returns success only for *queuing*, and deletes directories only if empty ([MoveFileExW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw)). No single documented reboot API exists; MSI exposes `MsiSystemRebootPending` during installation ([Property Reference](https://learn.microsoft.com/en-us/windows/win32/msi/property-reference)). Check the rename value; treat other reboot keys as observed.

## 3. Fast NTFS scanning

WizTree’s vendor says it “reads the hard drive’s Master File Table (MFT) directly”, requires admin for high-speed NTFS scanning, falls back for non-NTFS/network drives, and “correctly handles hard linked files” ([diskanalyzer.com](https://diskanalyzer.com/), [FAQ](https://www.diskanalyzer.com/faq)). Its exact API calls are **not verified** (closed source). A voidtools forum post states it keeps its index from “the MFT and the USN Journal”; a forum thread confirms hardlink deletion is not logged by USN and can be missed ([t=9128](https://www.voidtools.com/forum/viewtopic.php?t=9128), [t=6189](https://www.voidtools.com/forum/viewtopic.php?t=6189)).

Documented primitives: `FSCTL_ENUM_USN_DATA` enumerates MFT records from a NTFS volume handle, feeding the first output record back as the next start ([docs](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_enum_usn_data)). `FSCTL_GET_NTFS_FILE_RECORD` returns the first in-use record ≤ the requested reference, so IDs may differ ([docs](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_get_ntfs_file_record)). `FSCTL_GET_NTFS_VOLUME_DATA` and `FSCTL_GET_RETRIEVAL_POINTERS` give record sizes and map fragmented `$MFT` extents ([volume data](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_get_ntfs_volume_data), [retrieval pointers](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_get_retrieval_pointers)). `GetFileInformationByHandleEx` yields `FILE_ID_INFO` (volume + 128-bit ID), `FILE_STANDARD_INFO` (AllocationSize/EOF/NumberOfLinks) and `FILE_STREAM_INFO` for ADS; AllocationSize is the sparse/compressed truth ([FILE_ID_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_id_info), [FILE_STANDARD_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_standard_info)). `NtQueryVolumeInformationFile` is user-mode-callable via ntdll at PASSIVE_LEVEL ([docs](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-ntqueryvolumeinformationfile)).

Open-source equivalents: **WinDirStat 2** is a real MFT reader — `FinderNtfs::LoadRoot` opens `$MFT::$DATA`, gets extents, reads with `FILE_FLAG_NO_BUFFERING`, applies USA fixups, merges extension records, and handles `WofCompressedData`, sparse and hardlinks ([FinderNtfs.cpp](https://github.com/windirstat/windirstat/blob/4c24e70/windirstat/FinderNtfs.cpp), GPL-3.0). **MFTECmd** parses `$MFT`, `$J`, `$LogFile`, `$Boot`, `$SDS`, `$I30` offline, built on the MIT `MFT` library ([csproj](https://github.com/EricZimmerman/MFTECmd/blob/b1f668d/MFTECmd/MFTECmd.csproj), [MFT](https://github.com/EricZimmerman/MFT)). [dust](https://github.com/bootandy/dust) and [gdu](https://github.com/dundee/gdu) are traversal-only, and [QDirStat](https://github.com/shundhammer/qdirstat) is a Unix traversal tool — none read NTFS metadata.

Rust crates: [`usn-journal-rs`](https://crates.io/crates/usn-journal-rs) (USN + MFT), [`mft`](https://crates.io/crates/mft), [`ntfs`](https://crates.io/crates/ntfs), [`ntfs-reader`](https://crates.io/crates/ntfs-reader), plus [`jwalk`](https://crates.io/crates/jwalk), [`file-id`](https://crates.io/crates/file-id) and [`windows`](https://crates.io/crates/windows) for `DeviceIoControl`.

Pitfalls: MFT/USN need admin and NTFS; hardlinks must be de-duplicated by file ID or they double-count; sparse/compressed files must use allocated size; ADS is invisible to `EndOfFile`; MFT is fragmented; USN wraps and does not log hardlink deletes reliably; ReFS/exFAT need a traversal fallback; USN records carry parent references, not full paths.

## 4. Czkawka

Duplicate modes are name, size, size+name and hash; hash mode prehashes a prefix, caches results, then fully hashes with BLAKE3/CRC32/XXH3 ([`duplicate/core.rs`](https://github.com/qarmin/czkawka/blob/eb8b91d/czkawka_core/src/tools/duplicate/core.rs), [`HashType`](https://github.com/qarmin/czkawka/blob/eb8b91d/czkawka_core/src/common/model.rs#L69-L81)). Hardlinks are collapsed with `file_id::get_high_res_file_id` before comparison ([`filter_hard_links`](https://github.com/qarmin/czkawka/blob/eb8b91d/czkawka_core/src/tools/duplicate/mod.rs#L138-L165)); `hide_hard_links` is a user option. Safety/UX: dry-run, min/max size, excluded/reference folders, single- and group-delete confirmations, move-to-trash, and selection policies (oldest/newest/smallest/biggest); hardlink replacement writes a temp file then renames as rollback ([`deletion.rs`](https://github.com/qarmin/czkawka/blob/eb8b91d/czkawka_core/src/common/deletion.rs), [`fs_ops.rs`](https://github.com/qarmin/czkawka/blob/eb8b91d/czkawka_core/src/common/fs_ops.rs)). Large-file mode sorts by size and keeps top N ([`big_file/core.rs`](https://github.com/qarmin/czkawka/blob/eb8b91d/czkawka_core/src/tools/big_file/core.rs)). MIT-licensed.

## 5. Cleanup safety

BleachBit has 108 XML cleaners. Each `<action command="delete" search="deep" regex=... wholeregex=... nwholeregex=... path=... os=... skip_open=...>` is parsed by CleanerML from user/system/personal directories ([`CleanerML.py`](https://github.com/bleachbit/bleachbit/blob/07471fb/bleachbit/CleanerML.py), [`deepscan.xml`](https://github.com/bleachbit/bleachbit/blob/07471fb/cleaners/deepscan.xml)). It imports Winapp2.ini and offers `--update-winapp2` ([`Winapp.py`](https://github.com/bleachbit/bleachbit/blob/07471fb/bleachbit/Winapp.py), [`CLI.py`](https://github.com/bleachbit/bleachbit/blob/07471fb/bleachbit/CLI.py)). `protected_path.xml` only **warns** before protected paths are added ([`ProtectedPath.py`](https://github.com/bleachbit/bleachbit/blob/07471fb/bleachbit/ProtectedPath.py)); there is no quarantine or rollback, and wiping is irreversible. Untrusted cleaners may not run process-kill commands ([CleanerML](https://github.com/bleachbit/bleachbit/blob/07471fb/bleachbit/CleanerML.py#L34-L38)). BCU’s Recycle Bin + `.reg` export + restore point is the practical model.

For locked files, `MoveFileEx` only queues work: surface it as “pending reboot”, never as freed space, and walk directory contents first because directories are deleted only when empty (`src-tauri/src/locker.rs`). No mature rollback library exists; combine `trash`, Restart Manager ([`RmStartSession`](https://learn.microsoft.com/en-us/windows/win32/api/restartmanager/nf-restartmanager-rmstartsession)) and a quarantine store. The [`restart-manager`](https://crates.io/crates/restart-manager) crate is 0.1.0 — too immature.

## 6. What PurgeKit is missing

Already covered: inventory, bulk queue, snapshots/USN, leftovers/quarantine, autoruns, PATH, caches, sweeper, WSL, CLI, restore points and `WinVerifyTrust`; Geek’s advertised force removal and Store-app removal ([geekuninstaller.com](https://geekuninstaller.com/)) are largely matched. Gaps:

1. **Inventory correctness.** `SystemComponent==1` is hard-skipped (`src-tauri/src/scanner/registry.rs`) instead of default-hidden with a toggle; MSI uses `MsiEnumProductsW`/`MsiGetProductInfoW` (`scanner/msi.rs`) instead of the Ex APIs; only HKCU/HKLM are read; Appx is listed with `Get-AppxPackage -AllUsers` (`scanner/uwp.rs`) but removed for the current user (`commands.rs`), and provisioned packages are never removed; `Wow6432Node` is read literally.
2. **Portable/orphaned apps.** No `DirectoryFactory` equivalent; BCU’s depth-2, ≤40-exe, known-folder-skipping scan is directly portable.
3. **Fast disk explorer / duplicates.** None; recursive logical-size sums (`scanner/project_sweeper.rs`) overstate sparse/compressed files.
4. **Trust as data.** `WinVerifyTrust` is shown only as a boolean and gates elevated uninstallers (`winutil.rs`, `scanner/registry.rs`); signer/publisher is not surfaced, and catalog signatures are ignored (generic verification returns `TRUST_E_NOSIGNATURE` for catalog-signed `cmd.exe`; use `WTD_CHOICE_CATALOG` — [WINTRUST_DATA](https://learn.microsoft.com/en-us/windows/win32/api/wintrust/ns-wintrust-wintrust_data)).
5. **Rules channel and export.** Presets are hardcoded; there is no signed rule feed (BleachBit/Winapp2 is the model) and no JSON/CSV audit export or CLI parity for inventory/leftovers/export.
6. **USN tracker quality.** `tracker.rs` reads one 64 KB buffer, returns bare filenames without parent paths, and ignores journal wrap; use `usn-journal-rs` or MFT parent references.
7. **Pending reboot UX.** Scheduled deletions are not surfaced as a queue or report.

Non-gaps: orphaned services/tasks/shortcuts (`autoruns.rs`, `com_purger.rs`), batch queue, restore points.

## Techniques ranked by value to PurgeKit

1. **MFT explorer with traversal fallback** (high/high). WinDirStat 2’s sequence: volume data → extents → raw reads → fixups → merge; implement with `mft`/`usn-journal-rs`, hardlink/sparse aware. GPL-3.0 means study, not copy.
2. **Context-correct inventory** (high/low): HKU SIDs, Ex APIs, `msiexec /x`, Appx all-users/provisioned, SystemComponent toggle.
3. **Confidence leftovers with reasons** (high/low): Sift4 + publisher trim + containment + similar-name penalty; default Good.
4. **Recycle Bin/`.reg`/restore point** (high/low) beside quarantine.
5. **Portable/orphaned directory scan** (medium/low) with “uninstall from folder”.
6. **Duplicate/large-file finder** (medium/medium): size → prefix hash → full hash, `file_id`, trash, dry-run.
7. **Signed rules channel** (medium/medium): schema-validated, hash-pinned, no arbitrary process actions.
8. **JSON/CSV export + CLI parity** (medium/low): inventory, leftovers, pending reboot.
9. **Catalog-aware signature field** (medium/low): signer, embedded vs catalog, timestamp.
10. **Pending-reboot center** (medium/low): list queued paths and bytes, never count them as freed.

## Anti-patterns to avoid

- **`cmd /C <registry string>` with a character blocklist** (`src-tauri/src/commands.rs`). `%`, `^`, quotes and parentheses survive; parse argv and spawn directly, as BCU does.
- **Reading/writing literal `Wow6432Node`** instead of `KEY_WOW64_*`; Microsoft reserves the physical path.
- **Hard-hiding `SystemComponent` entries**; you lose real apps and cannot audit them.
- **Using non-Ex MSI APIs, or listing Appx for all users but removing only the current user**; this misses per-user products and leaves provisioned packages.
- **Treating logical file size as disk usage** for sparse/compressed files, or double-counting hardlinks.
- **Trusting `EstimatedSize`** (KB, often stale, sometimes a string) as measured size.
- **Treating `MoveFileEx` success as deletion**; it only queued a registry entry, directories must be empty, remote paths are invalid.
- **Using the USN journal as an undo log**; Microsoft states it does not record enough to reverse changes ([Change Journal Records](https://learn.microsoft.com/en-us/windows/win32/fileio/change-journal-records)).
- **Copying GPL code** (WinDirStat 2, BleachBit) into a proprietary codebase; BCU is Apache-2.0, Czkawka/MFT are MIT.

## What to build next

1. **Inventory correctness**: HKU SIDs, Ex APIs, MSI `/x`, Appx all-users/provisioned, SystemComponent toggle, `KEY_WOW64_*`.
2. **Portable app discovery**: BCU-style directory factory, user-confirmed registration/uninstall.
3. **Disk explorer MVP**: NTFS MFT scan + traversal fallback, hardlink/sparse aware, top-files tree.
4. **Leftover scoring v2**: Sift4 + confidence reasons + known-folder deny list, default threshold Good.
5. **Rules + report channel**: signed XML/JSON rules with exclusions; `purgekit export --json`; pending-reboot report.
6. **Duplicate finder** after the explorer: Czkawka pipeline with `file_id` and trash.
